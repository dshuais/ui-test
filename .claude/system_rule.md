# UI自动化代码编写强制规则，所有生成代码必须严格遵守

## 1、分层规范
1. 严格使用PO模式，base_page作为所有页面父类，所有Page类继承BasePage
2. pages层：仅定义元素定位器、封装页面动作方法，方法只做操作，不加assert断言
3. cases层：组装业务流程，调用page方法，编写断言校验结果
4. 所有文件导入路径使用相对导入，保证项目任意位置运行不会报导入错误

## 2、元素与等待规范
1. 优先使用data-testid > css选择器 > xpath；xpath只允许使用相对xpath
2. 全程禁用time.sleep固定强制等待，统一使用base_page封装的显式等待方法
3. 页面跳转、接口加载必须增加网络空闲等待
4. 所有操作方法增加异常捕获，操作失败自动调用截图方法保存至reports/screenshots

## 3、数据与配置规范
1. 环境地址、账号、超时、浏览器模式全部存放于data下json文件，代码禁止明文写死数据
2. 工具类统一在common/utils读取json配置，对外提供读取方法

## 4、日志与报告
1. 所有关键步骤打印分级日志（info正常步骤，error异常信息）
2. 用例失败自动截图，截图名称携带用例名称+时间戳
3. Allure报告添加用例标题、模块标签、功能标签、步骤注解

## 5、代码格式
1. 代码增加必要注释：元素用途、方法作用
2. 浏览器夹具使用session级别创建浏览器进程，function级别隔离页面上下文
3. 兼容windows与macOS系统路径，使用pathlib处理文件路径

## 6、测试执行约束
1. 用户说"测试XX模块"时，只运行该模块的用例（如 pytest cases/test_xxx.py），不重跑全量
2. 当前模块内尽可能全面覆盖（页面加载、搜索、Tab切换、新增、编辑等所有功能）
3. 只有用户明确要求"跑全量"时才执行 pytest cases/
