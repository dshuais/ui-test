# UI自动化代码编写强制规则，所有生成代码必须严格遵守

## 1、分层规范
1. 严格使用PO模式，base_page作为所有页面父类，所有Page类继承BasePage
2. pages层：仅定义元素定位器、封装页面动作方法，方法只做操作，不加assert断言
3. cases层：组装业务流程，调用page方法，编写断言校验结果
4. 所有文件导入路径使用相对导入，保证项目任意位置运行不会报导入错误

## 2、元素与等待规范
1. 优先使用data-testid > css选择器 > xpath；xpath只允许使用相对xpath
2. 全程禁用time.sleep固定强制等待，统一使用base_page封装的显式等待方法
3. 页面跳转、接口加载必须增加网络空闲等待
4. 所有操作方法增加异常捕获，操作失败自动调用截图方法保存至reports/screenshots

## 3、数据与配置规范
1. 环境地址、账号、超时、浏览器模式全部存放于data下json文件，代码禁止明文写死数据
2. 工具类统一在common/utils读取json配置，对外提供读取方法

## 4、日志与报告
1. 所有关键步骤打印分级日志（info正常步骤，error异常信息）
2. 用例失败自动截图，截图名称携带用例名称+时间戳
3. Allure报告添加用例标题、模块标签、功能标签、步骤注解

## 5、代码格式
1. 代码增加必要注释：元素用途、方法作用
2. 浏览器夹具使用session级别创建浏览器进程，function级别隔离页面上下文
3. 兼容windows与macOS系统路径，使用pathlib处理文件路径

## 6、测试用例内容与逻辑约束（核心）

### 6.1 源码扫描范围与覆盖完整性
1. 扫描源码范围：router（路由路径）、page 组件（搜索表单字段、工具栏按钮、表格列、行操作按钮、Tab 页、Modal 弹窗）、model（API 接口）
2. **功能覆盖必须完整**：扫描后必须覆盖该模块所有功能，包括但不限于：
   - 页面加载/列表加载
   - 搜索（按各字段关键词搜索）
   - Tab 切换
   - 新增/创建
   - 编辑/修改
   - 查看详情
   - 禁用/启用（状态切换）
   - 删除
   - 导入/导出
   - 刷新
   - 凡源码中出现的操作按钮、功能入口，**必须全部生成对应的测试用例**，不得遗漏
3. **一个模块一个用例文件**：扫描一个模块生成一个 `test_xxx.py`，不要将一个模块的用例拆分到多个文件
4. 列设置、分页切换等非业务功能暂时不需要覆盖

### 6.2 测试数据共享规则（关键）
1. **涉及新增、修改、删除等数据操作的，统一使用同一条生成的数据贯穿整个测试类**，不得每条用例都新增一条
2. 测试数据在 class 级别的 `shared_page` fixture 中生成一次，存入类变量，供所有用例共享
3. 数据名必须带时间戳后缀 `str(int(time.time()))[-6:]` 确保唯一性，避免与已有数据冲突
4. 数据命名前缀统一：
   - 自动化测试 + 时间戳（如"自动化测试123456"）
   - 自动化地址 + 时间戳
   - 自动化商品 + 时间戳
5. 最后一条用例必须执行删除/清理，确保测试不残留数据

### 6.3 用例编排顺序
1. 用例按业务逻辑顺序排列：
   ```
   test_01_add      → 新增数据
   test_02_edit     → 编辑该数据（如有）
   test_03_disable  → 禁用该数据
   test_04_enable   → 重新启用该数据
   test_05_delete   → 删除该数据（清理）
   ```
2. 无删除操作的模块（如商品管理只有新增→禁用→启用），最后一步不做删除

## 7、验证与截图约束
1. **只在操作完成、结果可验证的时刻截图**，不截弹窗、不截表单填写过程、不截中间加载态
2. 生命周期类用例的截图时刻：
   - 新增后 → 列表中出现该数据时截图
   - 编辑后 → 列表中的数据已更新时截图
   - 禁用/启用后 → 状态已切换时截图
   - 删除后 → 列表中该数据消失时截图
3. 功能验证类用例的截图时刻：
   - 页面加载完成 → 表格渲染完成时截图
   - 搜索完成后 → 搜索结果展示时截图
4. 截图通过 `allure.attach` 附加到验证步骤中，同时在 conftest 的用例结束时截一张终态图
5. 截图命名包含用例名+时间戳，存放在 `reports/screenshots`

## 8、测试执行约束
1. 用户说"测试XX模块"时，只运行该模块的用例（如 `pytest cases/test_xxx.py`），不重跑全量
2. 所有关键步骤打印分级日志（info正常步骤，error异常信息）
3. 用例失败自动截图，截图名称携带用例名称+时间戳

## 9、测试完成输出
1. 测试完成后必须运行 python3 generate_report.py 生成 HTML 报告
2. 必须在终端输出完整测试总结（模块名、用例数、通过/失败数、通过率、耗时、操作覆盖、每条用例步骤链）
3. 测试完成后不要问"还要继续吗"，等待用户下一条指令
